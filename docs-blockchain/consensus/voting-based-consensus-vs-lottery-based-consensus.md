# Voting-based consensus vs Lottery-based consensus

## Voting-based consensus vs Lottery-based consensus



| Voting-based (BFT) consensus                                                                                                                                                                                                                                                                                                                                  | Lottery-based consensus                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <p>a group of <strong>known/registered validators</strong> run rounds of <mark style="color:blue;"><strong>authenticated voting</strong></mark> (prepare/commit phases) </p><p>to agree on a value with deterministic finality </p><p>under a <mark style="color:blue;"><strong>Byzantine-tolerance bound</strong></mark> (typically &#x3C;1/3 malicious)</p> | <mark style="color:blue;">**participants**</mark> are <mark style="color:blue;">**pseudo-randomly selected**</mark> (**lottery**, **VRF**, **beacon**, **stake-weighted**) to be proposer(s) or committee members for a slot/round            |
| <p>Examples: <code>PBFT</code>, <code>Tendermint</code>, <code>HotStuff</code></p><ul><li>these are pure voting protocols — leader election can be <em><mark style="color:pink;">round-robin</mark></em> or <em><mark style="color:pink;">deterministic</mark></em>, <strong>not random</strong></li></ul>                                                    | <p>Examples: <code>Algorand</code>, <code>Ouroboros Praos</code>, many <code>PoS</code> designs</p><ul><li>selection provides <mark style="color:pink;"><strong>Sybil resistance</strong></mark> and scales to large validator sets</li></ul> |
| <p>Properties: </p><ul><li>deterministic/fast finality</li><li>requires O(n^2) or O(n) messaging depending on protocol</li><li>assumptions about validator set size and identity</li></ul>                                                                                                                                                                    |                                                                                                                                                                                                                                               |
